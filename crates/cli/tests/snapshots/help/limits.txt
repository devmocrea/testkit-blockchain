Find the largest input a contract function handles before it fails

Invokes --fn on the compiled .wasm in a local Soroban host (no
network), increasing the --ramp parameter: from --start (default 0) it
probes --start plus k times --step for k = 0, 1, 2, 4, ..., until a call
fails, then binary-searches between the last success and the first
failure. Each attempt runs in its own subprocess. Values above 16777216
(2^24) in magnitude are not tried, and a Vec ramp stops at 1024 items.
Prints the last successful value with the CPU instructions and memory
bytes it used.

Limitations:
  - --start and --step must keep every probe inside the ramp type: a
    u32 ramp cannot go below 0, and --step cannot exceed the type's range.
    A negative --step probes downwards, into negative values.
  - --ramp accepts u32/i32/u64/i64/u128/i128 (ramped as the value) and
    `Vec<T>` (ramped as its length), where T is Address, bool, an
    integer, Symbol, String or Bytes. Each `Vec<Address>` item is a
    distinct generated address.
  - Other parameters get these defaults: Address, a generated address
    (a parameter named `token` gets a funded Stellar Asset Contract);
    bool, false (or the value of --bool-default); u32, i32, u64, i64,
    u128 and i128, 1; Symbol, `x`; String and Bytes, empty; `Vec<T>`,
    empty; `Option<T>`, None.
  - Rejected with an error that names the type: Map, Tuple, Result,
    BytesN, U256, I256, Timepoint, Duration, Val, Error, Void,
    MuxedAddress and user-defined types. A `Vec<T>` with one of these
    elements is rejected as a ramp, though it still defaults to empty.
  - --auth-mode sets how authorization is mocked: all (default)
    approves every entry, root-only approves only root invocation
    auth, and none installs no mocks.
  - --repeat N measures the final value N times and reports the median
    with its min and max.
  - Ledger reads/writes and transaction size are not measured; they
    need network-backed transaction simulation.

Usage: soroban-testkit limits [OPTIONS] --contract <PATH> --fn <NAME> --ramp <PARAM>

Options:
      --contract <PATH>
          Path to the compiled contract .wasm file
          (e.g. `target/wasm32v1-none/release/<crate>.wasm`)

      --no-color
          Never emit ANSI color codes, here or from tools this command runs
          (e.g. cargo). Same as setting the `NO_COLOR` environment variable

      --fn <NAME>
          The contract function to ramp, as named in the contract's spec

  -q, --quiet
          Print only results and errors; suppress advisory notes. Cannot be
          combined with --verbose

      --ramp <PARAM>
          The parameter of --fn to increase on each attempt: an integer type
          (ramped as the value) or `Vec<T>` (ramped as its length)

  -v, --verbose
          Print extra diagnostics (commands run, files scanned) to stderr

      --start <N>
          First ramp value to probe (default 0), within the ramp parameter's type range
          
          [default: 0]

      --step <N>
          Step between ramp values (default 1; negative probes downwards). Probes are start + k*step for k = 0, 1, 2, 4, ...
          
          [default: 1]

      --jobs <N>
          Probe up to N ramp values at once (1 to 8, default 1)
          
          [default: 1]

      --probe-timeout <SECONDS>
          Stop an individual probe after N seconds (default 120; minimum 1)
          
          [default: 120]

      --repeat <N>
          Measure the final value N times (1 to 16, default 1). With N above 1, the report gives the median with the min and max
          
          [default: 1]

      --dry-run
          Generate and print one probe's arguments without invoking the contract. This validates the contract spec and is useful when diagnosing defaults

      --bool-default <PARAM=BOOL>
          Override a non-ramp bool parameter's default (repeatable): --bool-default enabled=true

      --auth-mode <AUTH_MODE>
          Authorization mock scope: all (default), root-only, or none

          Possible values:
          - all:       Approve every authorization entry, including nested invocations
          - root-only: Approve only authorization required by the root invocation
          - none:      Do not install authorization mocks
          
          [default: all]

      --json
          Print the result as a JSON document (`schema_version` 1) on stdout

  -h, --help
          Print help (see a summary with '-h')

EXAMPLES:
    soroban-testkit limits --contract target/wasm32v1-none/release/my_contract.wasm --fn batch_payout --ramp recipients
    soroban-testkit limits --contract my_contract.wasm --fn transfer --ramp amount
    soroban-testkit limits --contract my_contract.wasm --fn transfer --ramp amount --bool-default paused=true --repeat 5
