Static checks over a contract crate (not a security product)

Parses every .rs file under PATH and reports three patterns:
  - a contract entry point (a `pub fn` of a `#[contractimpl]` impl, or
    any fn of a `#[contractimpl]` trait impl) taking an Address
    parameter that never calls require_auth
  - arithmetic (+ - * /) on an i128-typed binding outside a
    checked_/saturating_/wrapping_ call
  - a persistent()/temporary() storage read with no extend_ttl in the
    same function

Each function is checked against its own body; functions nested in it
are checked separately, so each finding is reported once. Use --rule
to run only some rules, or --exclude-rule to skip some, and
--include/--exclude to choose which files are audited.

These are syntactic heuristics: findings can be false positives, and
no findings does not mean a contract is secure. Files that fail to
parse are not audited; each is listed with its parse error (as a
warning on stderr, or in the JSON `skipped` field).

Exit status: 0 when the scan completes; 1 when --strict is passed and
findings are reported; 2 for invalid input, which is a PATH that is
missing or unreadable, or, with --strict, a file that fails to parse.

Usage: soroban-testkit audit [OPTIONS] [PATH]

Arguments:
  [PATH]
          Directory or .rs file to audit; directories are scanned recursively
          for .rs files. Pass `-` to read a single source file from stdin
          (for editor integrations that audit unsaved buffers)
          
          [default: .]

Options:
      --no-color
          Never emit ANSI color codes, here or from tools this command runs
          (e.g. cargo). Same as setting the `NO_COLOR` environment variable

      --strict
          Exit 1 if any findings are reported, or 2 if a file failed to parse.
          Without it, findings are printed and the command still exits 0

      --json
          Print findings as a JSON document (`schema_version` 1) on stdout
          instead of text

  -q, --quiet
          Print only results and errors; suppress advisory notes. Cannot be
          combined with --verbose

      --rule <RULE>
          Run only this rule (repeatable, or comma-separated). Every rule
          named is run; rules not named are skipped. Without --rule, all
          rules run

          Possible values:
          - missing-require-auth:      An entry point's Address parameter that is never checked with require_auth
          - unchecked-i128-arithmetic: Raw `+ - * /` on an i128 value
          - missing-ttl-bump:          A persistent/temporary storage read with no extend_ttl

  -v, --verbose
          Print extra diagnostics (commands run, files scanned) to stderr

      --exclude-rule <RULE>
          Skip this rule (repeatable, or comma-separated). Applied after
          --rule; naming a rule in both is an error

          Possible values:
          - missing-require-auth:      An entry point's Address parameter that is never checked with require_auth
          - unchecked-i128-arithmetic: Raw `+ - * /` on an i128 value
          - missing-ttl-bump:          A persistent/temporary storage read with no extend_ttl

      --include <GLOB>
          Audit only .rs files matching this glob (repeatable, or
          comma-separated). Globs match paths relative to PATH with `/`
          separators: `*` and `?` stay within one path segment, `**` spans
          any number of segments, and a glob without `/` matches a file or
          directory name at any depth. A file also matches when one of its
          parent directories does. Without --include, every .rs file is
          audited

      --exclude <GLOB>
          Skip .rs files and directories matching this glob (repeatable, or
          comma-separated), e.g. generated or vendored code. Same syntax as
          --include and applied after it; skipped directories are not read

  -h, --help
          Print help (see a summary with '-h')

EXAMPLES:
    soroban-testkit audit ./src
    soroban-testkit audit ./src --strict
    soroban-testkit audit ./src --rule missing-require-auth --rule missing-ttl-bump
    soroban-testkit audit ./src --exclude-rule unchecked-i128-arithmetic
    soroban-testkit audit . --exclude target --exclude '**/generated/**'
    soroban-testkit audit . --include 'contracts/**' --exclude '*_test.rs'
    soroban-testkit audit ./src --json | jq '.findings'
